# Site audit — 2026-08-11

Two agents swept the running app: a usability tester driving a browser as a
first-time freelance designer across 29 routes, and an SEO + accessibility
auditor measuring computed values rather than impressions.

**Already fixed** in [#220](https://github.com/VASARI-STUDIO/UIL4B/pull/220):
the `--t3` contrast failure, the badge contrasts, the invisible slider/select
focus rings, the leaked `feedback.submitError` key, the unlabelled prompt
search, and the stale "Premium Plus" text on `/sitemap`.

Everything below is **open**. Ordered by impact, with the evidence attached so
none of it has to be re-measured.

---

## P1 — Every "start free" CTA lands on a "Welcome Back" sign-IN form

Four labels promising *new account, free* all deliver *returning user, sign in*,
with signup demoted to a small text link underneath:

- homepage hero **"Start building free →"** → `/login`
- homepage footer **"Start building free →"** → the same modal, in place
- header **"Start for Free"**
- `/discover/prompts` **"Upgrade to Pro"** → `/checkout?plan=yearly` → `/login`,
  losing the plan context on the way

`LoginPopup` already has an `isSignup` mode with the right copy ("Create your
free account"). The fix is to open in it from these four entry points.

Related: the same label is implemented two ways — the hero navigates to
`/login`, the footer opens a modal in place. Escape on `/login` navigates to
`/home` rather than back, and drops focus to `<body>`.

**This is the cheapest high-traffic fix on the list.**

## P1 — No prerendering: every route serves the homepage's meta to non-JS crawlers

`curl http://localhost:5173/typescale` returns the homepage `<title>`,
description, `og:url` and — critically — `<link rel="canonical"
href="https://www.uil4b.com">`. Per-route meta is applied client-side only by
`updateRouteMeta()` in a `useEffect`, and there is no prerender step.

Consequences: every social unfurler (none run JS) shows the homepage card for
every shared tool URL; ~26 URLs all declare themselves canonical to `/`, which
is an explicit instruction to drop them from the index. The `<noscript>` block
is homepage copy on every URL, so a non-JS crawler also sees ~26 byte-identical
pages.

Fix: prerender the sitemap routes at build time and extract `PAGE_TITLES` /
`PAGE_DESCRIPTIONS` out of `App.jsx` into a module the build script and the
runtime both import, so they cannot drift.

## P2 — Reflow: content is clipped, not scrollable, at 320px

`body { overflow-x: clip }` is set site-wide, so anything wider than the
viewport is silently cut off rather than reachable (WCAG 1.4.10). Measured at
320×800:

| Route | Clipped | Right edge vs 315px viewport |
|---|---|---|
| `/color/palette` | `.plb-col-tools` and 37 elements incl. `.plb-tool` | 363px |
| `/discover/prompts` | `.pl-add-btn` "Submit prompt" — the primary CTA | 535px |
| `/typescale` | `.tsc-row-text--heading` | 1374px |

At 390px the same `/discover/prompts` row hides "Submit prompt" and two of six
category filters with **no scrollable ancestor** — they are unreachable.

200% zoom (720×900) passes on all six audited routes.

## P2 — `/feedback` does not work

Submitting with content produced the raw key (fixed in #220), but the underlying
**submit still failed** — the error path is what surfaced. Submitting empty
gives no error text, no `aria-invalid` on any field, no toast, no focus move.
Four surfaces link here as the way to report problems.

## P2 — Soft 404s

`curl -o /dev/null -w "%{http_code}" /this-does-not-exist` → **200**, rendering
the homepage with `robots: index,follow`. Cause: `<Route path="*" element={
<Navigate to="/" replace />} />`. Needs a real 404 with `noindex`.

`/home` is a byte-identical duplicate of `/` that self-canonicalises, and is
linked from the nav logo on every page.

## P3 — Focus outline invisible on colour swatches

`.plb-tool` and `.plb-ramp-bar` on `/color/palette`, `.hw-pal-lock` /
`.hw-pal-copy` on `/`: outline `#2563eb` measured **1.05–2.51:1** against the
swatch colours. Structural — the swatch colour is user-chosen, so no single
outline colour can pass. #220 applied the white-inner/dark-outer dual ring to
the *sliders*; these button overlays still need it.

## P3 — Homepage cards that all go to the same two places

Six palette cards (Nimbus, Amethyst, Orchard, Ember, Slate, Bloom), each showing
its own swatches, **all** `href="/discover"`. Eight learn cards all
`href="/learn"`, and all eight display "Coming soon →" while being live links.
`/discover/palettes` already deep-links properly, so the capability exists.

## P3 — `/community` cards link to stock site homepages

Twelve named designs → four bare domains (`dribbble.com`, `awwwards.com`,
`behance.net`, `mobbin.com`). Reads as placeholder data on a page presented as
a real community.

## P3 — Font catalogue error blames the network

`/fontgallery` and `/fontpairs` both say Google's catalogue "couldn't be
reached", while `fonts.googleapis.com` and `fonts.gstatic.com` both return 200.
The *catalogue API* call is failing (likely a missing key), so the message sends
you looking in the wrong place.

## P3 — Header "Export" is a permanent dead end

All five formats carry "Soon" and the confirm button is disabled. It is the
thing the homepage sells ("hand off", "export-ready"), so it is where people go
to check the claim. Ties into item 13.

## P4 — Smaller items

- Missing from `sitemap.xml` but real, indexable pages: `/discover`, `/learn`,
  `/sitemap`. `/feedback` (26 words) should probably leave it.
- Legacy redirects are client-side 200s, not 301s — move to `vercel.json`.
- Heading skips: `/emoji`, `/privacy`, `/terms` all go h1 → h3.
- `/icons` and `/emoji` share an identical `<h1>`.
- One `og:image` for all routes; no per-route JSON-LD (`BreadcrumbList`,
  `Product`/`Offer` on `/plans`, `FAQPage` on `/help`).
- `/plans` description is 192 chars and will truncate in SERPs.
- Unlabelled inputs remain on `/color/contrast` (two hex fields — the page's
  whole job), `/color/tint`, `/fontgallery`. Their pickers say "Pick text colour
  colour".
- Header "Start for Free" is `aria-hidden="true"` + `tabindex="-1"` at
  `scrollY: 0` on `/` — a focusable-looking button inside an aria-hidden
  subtree, and no header signup control for AT users at the top of the page.
- Mobile menu opens without moving focus (`activeElement` stays `BODY`).
- `.sr-only` is not width-constrained; it only stays hidden because of
  `overflow-x: clip`.
- `/settings` is reachable signed out and offers "Start 7-day free trial"
  alongside "Sign in to upgrade" — and the trial is never mentioned on `/plans`.
- `/icons` says "click to copy clean SVG"; clicking opens a Customise dialog.

## Not checked — do not read as passing

- Dark theme contrast (the app force-resets to light).
- Any signed-in state, anywhere. `/alt-text`'s actual tool is behind auth.
- Screen-reader announcement with real AT.
- Text over gradients/images.
- Target size (2.5.8), pointer gestures, `prefers-contrast`.
- Keyboard/contrast/reflow on the 20 routes audited for SEO only.
- `/file-converter`'s upload and convert flow.

## What worked, and is worth not breaking

Skip link is the first tab stop on all six audited routes and actually moves
focus. No keyboard traps across 48-stop walks. Zero unnamed buttons or links on
any audited route. Modals (Export, Sign-in, Icon customiser) close on Escape and
return focus to the trigger. Mega-menu is fully keyboard-operable. Gated actions
produce a clear "don't worry, it's still free" dialog rather than failing
silently. `/discover/palettes` and `/discover/gradients` deep-link with full
state in the URL. Zero `<img>` without alt — there are no `<img>` elements at
all; it is all inline SVG.
