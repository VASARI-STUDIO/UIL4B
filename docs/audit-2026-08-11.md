# Site audit — 2026-08-11

Two agents swept the running app: a usability tester driving a browser as a
first-time freelance designer across 29 routes, and an SEO + accessibility
auditor measuring computed values rather than impressions.

**Already fixed** in [#220](https://github.com/VASARI-STUDIO/UIL4B/pull/220):
the `--t3` contrast failure, the badge contrasts, the invisible slider/select
focus rings, the leaked `feedback.submitError` key, the unlabelled prompt
search, and the stale "Premium Plus" text on `/sitemap`.

Everything below is **open**. Ordered by impact, with the evidence attached so
none of it has to be re-measured.

---

## P1 — Every "start free" CTA lands on a "Welcome Back" sign-IN form

Four labels promising *new account, free* all deliver *returning user, sign in*,
with signup demoted to a small text link underneath:

- homepage hero **"Start building free →"** → `/login`
- homepage footer **"Start building free →"** → the same modal, in place
- header **"Start for Free"**
- `/discover/prompts` **"Upgrade to Pro"** → `/checkout?plan=yearly` → `/login`,
  losing the plan context on the way

`LoginPopup` already has an `isSignup` mode with the right copy ("Create your
free account"). The fix is to open in it from these four entry points.

Related: the same label is implemented two ways — the hero navigates to
`/login`, the footer opens a modal in place. Escape on `/login` navigates to
`/home` rather than back, and drops focus to `<body>`.

**This is the cheapest high-traffic fix on the list.**

## P1 — No prerendering: every route serves the homepage's meta to non-JS crawlers

`curl http://localhost:5173/typescale` returns the homepage `<title>`,
description, `og:url` and — critically — `<link rel="canonical"
href="https://www.uil4b.com">`. Per-route meta is applied client-side only by
`updateRouteMeta()` in a `useEffect`, and there is no prerender step.

Consequences: every social unfurler (none run JS) shows the homepage card for
every shared tool URL; ~26 URLs all declare themselves canonical to `/`, which
is an explicit instruction to drop them from the index. The `<noscript>` block
is homepage copy on every URL, so a non-JS crawler also sees ~26 byte-identical
pages.

Fix: prerender the sitemap routes at build time and extract `PAGE_TITLES` /
`PAGE_DESCRIPTIONS` out of `App.jsx` into a module the build script and the
runtime both import, so they cannot drift.

## ~~P2 — Reflow: content is clipped, not scrollable, at 320px~~ — FIXED

All three routes now measure **zero** unreachable elements at 320px, and a
sweep across eight routes runs in CI (`21-reflow-320.spec.js`).

**One root cause explains all three, plus a fourth the audit missed.** A flex or
grid item defaults to `min-width: auto`, which refuses to shrink below its
content. So a `1fr` track quietly becomes as wide as its widest child, and an
`text-overflow: ellipsis` rule never fires. `overflow-x: clip` on body then
*hides* the consequence instead of producing the horizontal scrollbar that would
have made it obvious during development.

| Route | Was | Fix |
|---|---|---|
| `/color/palette` | `.plb-col-tools` at right:367 in a 315px viewport — lock, copy and delete unreachable on every colour | tools wrap to their own line, staying ≥32px. Shrinking five buttons into the ~206px beside the hex would have traded a 1.4.10 failure for a 2.5.8 one |
| `/discover/prompts` | `.pl-add-btn` — the primary CTA — at right:535, entirely off screen | the sort row's inline `style={{}}` became `.pl-sort` with `min-width:0`; the CTA takes a full-width line below 520px |
| `/typescale` | `.tsc-row-text` at 1328px inside a 247px row | `min-width:0` on the row, so the ellipsis the rule already asked for finally applies. **Font sizes are unchanged** — a type-scale tool that shrinks its own specimens is lying about the scale it exists to demonstrate |
| `/ratio` **(missed by the audit)** | `.rc-panel` forcing a 322px grid track | `min-width:0` |

**~~`.sr-only` is not width-constrained~~ — FALSE POSITIVE, verified.** The rule
is `position:absolute; width:1px; height:1px; overflow:hidden;
clip:rect(0,0,0,0)`. Setting body's `overflow-x` to `visible` and re-measuring
leaves the document scroll width exactly equal to the viewport — it does not
depend on the clip at all. Wide text *inside* it is clipped by the 1px parent
and never reaches the page. This is the second false positive found in this
document, after the `/color/contrast` labels.

The sweep therefore excludes two categories on principle: anything inside
`.sr-only` (visually hidden by design, and read by a screen reader regardless of
geometry), and `aria-hidden` nodes with no text (the homepage's
`.system-cta-beams` are animated light beams that are *meant* to run past the
fold — 1.4.10 is about content).

## ~~P2 — Soft 404s~~ — FIXED

*Was:* `curl -o /dev/null -w "%{http_code}" /this-does-not-exist` → **200**,
rendering the homepage with `robots: index,follow`, from
`<Route path="*" element={<Navigate to="/" replace />} />`. And `/home` was a
byte-identical duplicate of `/` that self-canonicalised, while being what the
nav logo links to on every page — so the internal link graph pointed at the copy
rather than at the homepage.

**Now:** a real [`NotFound`](../src/pages/NotFound.jsx) page that keeps the
visitor on the URL they typed and offers real destinations; a prerendered
`404.html` carrying `noindex,follow` for crawlers that never run JS; and the
vercel.json catch-all pointing at it instead of `index.html`. `/home` now
canonicals to `/`. 26 unit tests.

Three things worth recording:

- **The redirect hid broken links from us, not only from crawlers.** Teleporting
  someone to `/` makes a dead link look like it worked, so it never gets
  reported. The 404 links to `/feedback` for exactly that reason.
- **`index.html` already ships a static `robots` tag**, so *inserting* one into
  the 404 shell produced two contradictory directives in a single head. Google
  resolves that by taking the most restrictive, so it happened to behave — but
  relying on a tie-break is not the same as being correct. It is now substituted.
- **A `noindex` page gets no canonical at all.** Self-canonicalising asserts
  "this is the authoritative version of a real page" in the same head that says
  "do not keep this". Pointing it at `/` would be worse: it would funnel every
  typo's signals into the homepage.

**CI was never running the prerender.** The workflow ran `npx vite build`, not
`npm run build` — and only the npm script runs `scripts/prerender.mjs`. The step
production actually deploys therefore had no coverage at all, so a prerender
that crashed, or silently stopped matching index.html's tags, would have shipped
green. Both CI jobs now run `npm run build`.

## P4 — Smaller items

- ~~Missing from `sitemap.xml`~~ — **partly fixed, and this item was partly
  WRONG.** `/discover` and `/sitemap` are real pages and are now advertised.
  **`/learn` is not**: every entry in `LEARN_GROUPS` carries `soon: true` and the
  page's own copy reads "Learn is coming soon", so it resolves to `noindex`.
  Advertising it would have meant `sitemap.xml` saying "index this" about a page
  whose head says the opposite. A unit test now enforces that the sitemap never
  contains a route resolving to `noindex` — the invariant, rather than the
  instance.
- Legacy redirects are client-side 200s, not 301s — move to `vercel.json`.
- Heading skips: `/emoji`, `/privacy`, `/terms` all go h1 → h3.
- `/icons` and `/emoji` share an identical `<h1>`.
- One `og:image` for all routes; no per-route JSON-LD (`BreadcrumbList`,
  `Product`/`Offer` on `/plans`, `FAQPage` on `/help`).
- `/plans` description is 192 chars and will truncate in SERPs.
- ~~Unlabelled inputs on `/color/contrast`~~ — **FALSE POSITIVE, verified and
  corrected.** Both hex fields carry `id` + a matching `<label for>`
  (`ContrastChecker.jsx` `ColorField`), so they have proper accessible names.
  The audit's sweep only checked `aria-label` / `aria-labelledby` / `title` /
  `placeholder` and missed the label association — worth knowing before trusting
  the same check on `/color/tint` and `/fontgallery`, which are **unverified**
  and may be the same mistake. The *pickers* saying "Pick text colour colour"
  was real and is fixed.
- Header "Start for Free" is `aria-hidden="true"` + `tabindex="-1"` at
  `scrollY: 0` on `/` — a focusable-looking button inside an aria-hidden
  subtree, and no header signup control for AT users at the top of the page.
- Mobile menu opens without moving focus (`activeElement` stays `BODY`).
- ~~`.sr-only` is not width-constrained; it only stays hidden because of
  `overflow-x: clip`.~~ — **FALSE POSITIVE, verified.** See the Reflow section
  above: the rule carries its own `width:1px; height:1px; overflow:hidden;
  clip:rect(0,0,0,0)`, and with body's `overflow-x` set to `visible` the
  document scroll width still equals the viewport exactly.
- `/settings` is reachable signed out and offers "Start 7-day free trial"
  alongside "Sign in to upgrade" — and the trial is never mentioned on `/plans`.
- `/icons` says "click to copy clean SVG"; clicking opens a Customise dialog.

## Not checked — do not read as passing

- Dark theme contrast (the app force-resets to light).
- Any signed-in state, anywhere. `/alt-text`'s actual tool is behind auth.
- Screen-reader announcement with real AT.
- Text over gradients/images.
- Target size (2.5.8), pointer gestures, `prefers-contrast`.
- Keyboard/contrast/reflow on the 20 routes audited for SEO only.
- `/file-converter`'s upload and convert flow.

## What worked, and is worth not breaking

Skip link is the first tab stop on all six audited routes and actually moves
focus. No keyboard traps across 48-stop walks. Zero unnamed buttons or links on
any audited route. Modals (Export, Sign-in, Icon customiser) close on Escape and
return focus to the trigger. Mega-menu is fully keyboard-operable. Gated actions
produce a clear "don't worry, it's still free" dialog rather than failing
silently. `/discover/palettes` and `/discover/gradients` deep-link with full
state in the URL. Zero `<img>` without alt — there are no `<img>` elements at
all; it is all inline SVG.
