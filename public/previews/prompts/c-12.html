The measure is the decision you make first

Line length sets the leading, the type size, the grid and half of how a page feels. Most of us set it last, by accident, in a container.

Every argument about web typography eventually turns out to be an argument about the measure. Someone says the type is too small; it is not, the column is too wide. Someone says the page feels cramped; it is not, the leading is fighting a short line. The measure — the length of a line of text — is the first decision, and almost nobody makes it first.

What the measure is

The measure is how far the eye travels before it has to come back. At the end of every line the reader performs a return sweep: a fast movement back to the left edge and down one line. It is the least conscious and most fragile part of reading. When the line is long, the sweep has further to go and lands less accurately, and the reader re-reads a line or loses one. When the line is short, the sweep happens so often that it becomes the rhythm of the page, and the reader feels hurried.

So the measure is not a matter of taste. It is a mechanical setting, like the gear on a bicycle, and it has a range where the machine runs well.

Where 45 to 75 comes from

The number most often quoted — 45 to 75 characters, 66 as the ideal — comes from Robert Bringhurst, who was describing text set in a book, in a serif face, read by an adult who had chosen to read it. It is a good number. It is not a law, and the conditions matter.

Mid-century legibility research, most of it associated with Miles Tinker and Donald Paterson, had already established the shape of the finding: comprehension and reading speed hold steady across a band of line lengths and fall away at both ends. What the research did not give us is a single correct value, because the value moves with the size of the type, the leading, the face, and whether the reader is reading or scanning.

Treat 45–75 as the band, and then place yourself inside it deliberately:

  • Nearer 45 for reference material that is scanned, for sidebars, for anything set in two columns, and for text a reader dips into.
  • Around 66 for continuous prose — an essay, a long documentation page, a story.
  • Nearer 75 only with generous leading and a face with a small x-height, and only when the reader is settled.

Setting it in CSS

The instinct is to reach for max-width in pixels, which is fine until the type size changes and the measure quietly changes with it. The ch unit ties the container to the type instead: one ch is the advance width of the digit zero in the current font, which is close enough to an average character to be useful.

/* The container is described in characters, not pixels. */
.prose {
  max-width: 66ch;
  font-size: clamp(1rem, 0.94rem + 0.32vw, 1.125rem);
  line-height: 1.72;
  text-wrap: pretty;
}

The measure is now a function of the type size. Grow the type and the column grows with it, so the line still holds about sixty-six characters.

Two cautions. First, ch is measured on the zero of the current font, so a face with wide figures gives you a wider column than you asked for — check the result, do not trust the unit. Second, text-wrap: pretty only tidies the last lines; it is not a substitute for a sensible width.

A column that is too wide never looks wrong. It quietly costs the reader a line every few seconds, and they blame themselves for losing concentration.

Leading moves with it

Line length and line height are one decision, not two. A longer line needs more leading, because the return sweep needs a clearer target to land on; a short line needs less, or the lines stop reading as a paragraph and start reading as a list.

A working rule: at 45 characters set 1.5; at 66 set 1.7; at 75 set 1.8 and check it in the worst light you can find. If you change the measure later — and you will, when the sidebar arrives — change the leading in the same commit.

One test that catches almost everything Read three paragraphs of your own page on a phone, standing up, at the brightness you actually use outdoors. Every measure problem shows itself within about fifteen seconds, and nothing else you can do at a desk finds them as fast.

What breaks on a phone

On a narrow screen the measure is decided for you — a 390 px viewport with sensible margins gives about 38 characters at 17 px, which is at the short end of the band and perfectly readable. The failures are elsewhere.

Padding eaten by a card

A card inside a card inside a container leaves 22 characters a line. Text ends up in a gutter you did not design. Count characters, not nesting levels.

Headings set at body measure

A heading is scanned, not read, and it wants a shorter measure than the paragraph under it — around 20 to 30 characters. Give headings their own max-width and they stop breaking into three ragged lines.

Code blocks that force a scroll

A code block does not obey the measure and should not try to. Give it its own horizontal scroll, keep it inside the reading column, and never let it widen the page — a body that scrolls sideways is the one typographic failure a reader notices immediately.

A checklist

  • Set the measure in ch, in the same rule as the font size.
  • Count the characters on a line at your largest breakpoint — the actual characters, in a browser, not in the design file.
  • Move the leading whenever the measure moves.
  • Give headings, captions and pull quotes their own, shorter measures.
  • Let code blocks scroll inside the column; never let the page scroll sideways.
  • Read it on a phone, outdoors, standing up. ■
