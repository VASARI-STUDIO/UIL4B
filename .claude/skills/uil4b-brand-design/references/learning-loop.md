# Brand learning loop

## Goal

Turn reviewed experience and founder feedback into durable, scoped brand
knowledge without making the skill a pile of taste reactions.

## Capture a learning

Record:

1. **Trigger** — the surface, version, or review that produced the feedback.
2. **Observed response** — the user's wording or measured behaviour.
3. **Interpretation** — the likely design cause, clearly labelled as inference
   unless directly established.
4. **Decision** — preserve, revise, test, or deprecate.
5. **Scope** — component, flow, app surface, sales surface, or whole brand.
6. **Evidence** — screenshots, tests, user feedback, or code references.
7. **Status** — canonical, accepted, candidate, or deprecated.

## Promote carefully

- One reaction creates a candidate, not a universal rule.
- Repeated feedback across related surfaces can promote a candidate to accepted.
- Explicit founder direction can establish a canonical decision immediately.
- A working local solution should not become global until reuse is intentional.
- Record contradictions; do not silently erase earlier reasoning.

## Where to store changes

- Update `brand-foundation.md` for durable identity or positioning logic.
- Update `anti-slop-quality-bar.md` for a repeatable diagnostic or correction.
- Update `surface-principles.md` for product-versus-sales behaviour.
- Update live project docs or tokens for implementation truth.
- Keep task-specific acceptance criteria in the task, not this skill.

## Review cadence

After a meaningful design cluster:

1. Compare the implemented result with its intended emotional and functional
   outcome.
2. List patterns that earned reuse and patterns that caused generic or
   overproduced responses.
3. Promote only the lessons likely to help future surfaces.
4. Update the relevant reference and its decision status.
5. Check that agents still contain role logic only.

The aim is cumulative taste with traceable reasoning, not a growing blacklist.
